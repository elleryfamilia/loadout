# loadout v0.15.0 — learning (ambient harvest) design

- **Date:** 2026-07-09
- **Version note:** this release was numbered v0.14.0 throughout the planning arc, but v0.14.0 shipped 2026-07-09 (plan visualizer, release commit `aa28149`) from a parallel session — learning is therefore **v0.15.0**, and the deferred audit layer targets v0.16.
- **Status:** revised after adversarial critic pass (1 blocker + 6 majors + 5 minors folded in; structural cut: audit layer deferred to v0.16) AND cross-model review (codex gpt-5.5 xhigh, read-only repo access: 1 blocker + 5 majors + 1 minor, all folded in — lock fencing, two-stamp throttle, eventual-off semantics, gemini hook gating, hook ownership ids, claim lint gate, semantic-preservation wording) — awaiting user review
- **Supersedes:** the "learning" outline section of `design.md` (numbered v0.14.0 there; see version note). One decision there is explicitly reversed: harvest was "user-triggered only"; it is now **ambient after a one-time opt-in**. A second change of plan, made on critic findings: `loadout-audit` moves to the following release (see "Audit layer — deferred").
- **Related, not merged:** RS-3 (per-project journal for off-repo work) is a separate capture channel; if built later its notes may feed this inbox as `source: manual`. Nothing here depends on it.

## Objective

loadout learns from the user's own agent sessions without becoming the thing it positions against. After one explicit opt-in, loadout mines recent session transcripts for durable cross-project preferences and stages them as **candidate fragments** in an **inbox**; the user promotes or dismisses them in the studio. Harvesting runs as **one-shot, bounded, logged** invocations of an agent CLI the user already has — no resident daemon, no wall-clock scheduling, no token spend the user didn't cause and can't see.

## Hard constraints (unchanged, binding)

- No resident daemon. No OS-scheduled jobs (approach explored and rejected — see Decisions #1). No background polling loops.
- Session start must never block on an LLM call.
- No surprise token spend: explicit opt-in, per-machine activation, cheap-model default, hard per-run caps, every run logged and attributable to a user-caused event, and a spend ceiling that holds under crash conditions (Decision #3).
- Own-your-markdown: nothing enters a profile without the user pressing promote.
- Render-time rule intact: `refresh`/`run`/`render` themselves never make LLM calls; ambient work happens in a detached one-shot child, never inline.

## Architecture

One new module family, one worker, several thin trigger paths (session-end hooks plus the four loadout entry points), all funneling into the same throttle:

```
triggers (any of):                       worker (one per machine at a time):
  claude/gemini SessionEnd hook   ──┐      load harvest --ambient
  cursor stop hook                ──┤        1. lock (state dir, O_EXCL, {pid, started_at, token}
  load run   (pre-exec check)     ──┼──►        with the random fencing token minted HERE); if the
  load hook  (serve check)        ──┤           existing lock is stale (dead PID or age > 2×
  load refresh / studio (check)   ──┤           deadline): reclaim, count as a failure
  load harvest (manual)           ──┘        2. write scan stamp (fenced)
                                             3. read watermarks; collect eligible new slices
                                                (none → log a no-op, exit; spend stamp untouched)
                                             4. extract user messages (per-store readers, filters)
                                             5. redact_secrets on every slice
                                             6. write SPEND stamp, then ONE agent-CLI call
                                                (bounded, cheap model)
                                             7. lint+redact claims; merge → journal events
                                                (dedupe, suppressions); quotes → state-dir
                                                evidence store
                                             8. advance watermarks monotonically (never regress
                                                offsets; prune entries for deleted files);
                                                append log entry; release lock; exit
```

**Lock fencing** (codex finding 1): the fencing token is minted at lock acquisition, before any other side effect. **Every side effect is fenced** — scan stamp, spend stamp, the agent-CLI spawn itself, journal append, evidence write, watermark update, log append — each first re-reads the lock and proceeds only if it still holds its own token. A stale worker that resumes after its lock was reclaimed finds a different token and aborts before spending or writing, so the spend ceiling holds even under suspend/resume interleavings. Watermark updates are additionally monotonic (per-file max of current and new offset), so even a fencing bug cannot regress them into double-harvesting.

### Trigger fast path (no LLM, no spawn unless due)

Shared `learn::maybe_spawn(trigger)`: exit immediately unless ALL hold — `[learn] enabled = true` in config (already loaded at every trigger site, and read AFTER the flow's existing throttled auto-pull where one exists, so a synced disable lands before the check); per-machine activation ack present; `LOADOUT_LEARN != off` (user kill switch) and `LOADOUT_LEARN_WORKER` unset (recursion guard); scan stamp older than its debounce and spend stamp older than `learn.interval`. Residual cost when idle: the config field read plus stamp `stat()`s. Stale-lock handling lives in the worker (step 1), not the fast path — a crashed worker can never wedge triggering, and reclaim is counted and logged.

Session-end hook handler: reuse `load hook <agent>` invariants (quiet, stdout-silent, always exit 0, bounded stdin) with `--event session-end`; the payload's `transcript_path`/`session_id` (claude provides both — payload fields doc-verified at plan time: `session_id`, `transcript_path`, `cwd`, `hook_event_name`, `reason`) marks that session immediately eligible, bypassing the quiescence window. **Plan-time resolution:** SessionEnd fires for `-p` runs too, and `reason` does not reliably distinguish interactive from programmatic — so hook-named eligibility carries no exemption: the reader's `entrypoint`-based programmatic exclusion applies to hook-named sessions exactly as to scanned ones. Registration schema doc-verified (`hooks.SessionEnd: [{matcher?, hooks: [{type: "command", command, timeout}]}]`, matcher optional); `--bare` doc-verified to skip ALL hooks including SessionEnd (recursion guard layer 2 holds); `disableAllHooks` (top-level key) confirmed. Our hook entries set a short explicit `timeout` (SessionEnd default is 600s; ours needs ~10s since the handler only runs the fast path + detached spawn).

### Detached spawn

Double-spawn so the worker reparents to init before `run` exec()s the agent: trigger spawns an intermediate that spawns the real worker and exits; trigger waits only for the intermediate (ms). Worker: `setsid`, `process_group(0)`, stdio → log file, `nice`-d, hard wall-clock deadline (default 5 min) enforced internally; the agent-CLI call additionally bounded by `output_with_timeout`. Not a daemon: one job, user-caused trigger, bounded runtime, exits; a wedged worker is bounded by the deadline and, failing even that, by lock-staleness reclaim at the next worker start. Windows (spec-review amendment #5): **verified at plan time — dist-workspace.toml ships no Windows target** (aarch64/x86_64 apple-darwin + unknown-linux-gnu only), so the question is moot for shipped binaries; the code still guards the spawn path behind `#[cfg(unix)]` with a graceful "not supported" fallback so a source build on Windows degrades instead of breaking.

### Watermarks and eligibility

`state_dir/learn/watermarks.json` (versioned; newer-version refusal like the trust store). Per JSONL file (claude, codex): `{bytes_processed, mtime_seen}` — append-only stores resume by offset. Gemini `logs.json` is a rewritten array → processed-`sessionId` set. Entries whose files no longer exist are pruned on write (critic MINOR-4). Watermarks advance past **everything scanned** this run, including over-cap content that was dropped rather than extracted (Decision #3 amendment — drop, don't defer). Eligibility: mtime older than a ~20-min quiescence window (don't harvest a live session) OR named by the triggering hook payload. Ordering is crash-safe: journal events written first, watermark advanced second; content-hash dedupe makes replays idempotent. (The spend stamp at step 6 — not the watermark — is what bounds spend under crash replays.)

### Transcript readers (tier 1: claude, codex, gemini — all formats verified on this machine)

- **claude**: `~/.claude/projects/<munged-cwd>/*.jsonl`, lines typed `user`; skip subagent/sidechain files; skip programmatic sessions (marker verify at plan time; fallback heuristic per Decision #6).
- **codex**: `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`; `session_meta` carries `cwd` and `originator` (verified) — exec-mode sessions excluded.
- **gemini**: `~/.gemini/tmp/<project-hash>/logs.json` — user prompts with sessionId/timestamp; same programmatic-exclusion requirement.
- Deferred: opencode (tier-2), cursor chats (format unverified). A store that fails to parse is skipped with a log line — readers fail closed per-store, never abort the run.

Scope filter: `learn.scope = adopted` (default) keeps only sessions whose cwd resolves to a repo loadout has adopted/rendered (from the synced bindings/overlay records, src/binding.rs); `all` widens.

### Self-exclusion / recursion guards (four independent layers)

1. `LOADOUT_LEARN_WORKER=1` in the worker's env — every trigger site refuses to fire under it (env propagates through the nested agent CLI to any hook it spawns).
2. Agent-native: claude `--bare` + `--no-session-persistence` (no hooks, no transcript), codex `--ephemeral` (no session file).
3. cwd guard: worker runs in `state_dir/learn/work/`; readers drop any session whose cwd/project-hash matches it (covers gemini, which has no no-persist flag).
4. Prompt sentinel: readers skip sessions containing the harvest prompt's sentinel string.

### The extraction call

Prompt contains: instructions (extract durable, cross-project preferences/corrections; ignore project-specific and factual notes; output strict JSON schema), current fragment ids+descriptions (so candidates can say "refines fragment X" and exact duplicates are avoided), **pending candidates' exact claims** (reuse verbatim on re-observation — Decision #8) **passed as inert JSON data, never as prose instructions**, and the redacted user-message slices grouped by session. Output: `[{claim, evidence: [{session_ref, quote}], kind}]`. Worker validates strictly; malformed output → run logged as failed, nothing written, watermark NOT advanced (the spend stamp already spent this tick — by design, a bad run waits out the interval rather than retrying).

**Claim gate** (codex finding 6 — claims sync and re-enter future prompts, so they get the same deterministic defenses as rendered guidance): before a claim is written to a journal or anchored into a later prompt, it passes `redact_secrets` plus the injection lint (instruction-override phrasing, exfiltration-shaped URLs, hidden Unicode/control characters, code fences) and a length cap. A claim that fails the lint is quarantined: logged, surfaced in studio as "held by injection lint" with the matched pattern, never anchored into prompts, promotable only after the user edits it.

### Inbox model

Synced journal events (`~/.config/loadout/inbox/journal-<machine-id>.jsonl`): `observed {id, kind: candidate, source: session|repo|manual, claim, session_refs[{agent, session_id, ts}], produced_by{cli,model}, ts}` and `disposition {id, action: promote|dismiss|unsuppress, ts}`. Machine-local evidence store (`state_dir/learn/evidence/<id>.json`): quotes capped at 5 × ~200 chars, redacted before write. Folded candidate state: id, observation count (distinct session refs across journals), first/last seen, status, evidence-locality note.

### Surfaces

- **Snapshot**: at most ONE line, only when N>0: `loadout: N staged suggestions await review — load studio`.
- **Refresh**: same line; plus, when an ambient run happened since last refresh, one summary line: `learning: harvested 3 sessions via claude (haiku) — 2 new candidates`.
- **Studio Inbox page** (placement in nav at plan time): candidate list with claim, source, observation count, evidence (local or "recorded on <host>"); promote (pick new-fragment-or-merge + profiles; writes config through existing collector machinery; appends disposition) / dismiss (suppression); history panel folding `state_dir/learn/log.jsonl` (every run: ts, trigger, cli, model, sessions read, candidates, duration, outcome, token usage where the CLI reports it); suppression list with un-suppress.
- **CLI**: `load learn on|off|status|reset`. `on` = consent text naming exactly what will run and when, which hook files are edited, that claim text derived from sessions is stored in the synced loadout config (quotes stay local), the honest call ceiling, and a concrete metered-API cost estimate at default caps (computed from cap sizes at plan time, e.g. "up to roughly N¢ per run at current haiku-class pricing; pin `learn.cli` to a subscription-backed CLI if your API key is metered") — then activation + hook registration + offer of an immediate first run. `off` = per Decision #4. `reset` = re-baseline watermarks after corruption. `load harvest` = manual run, same worker path. Studio remains the review surface; headless boxes review on a studio-capable machine via sync (claims and counts sync; quotes don't — accepted limitation).
- **Doctor**: learn section (enabled/activated, last run, next eligibility, last error, hooks registered and well-formed, orphaned-hooks flag per Decision #4); nudge if learning is on but no trigger fired in 14 days. Doctor never triggers a harvest.

### Hook registration (tier 1: claude, cursor; gemini gated)

`HookRegistry` grows to a list with a format discriminator — **code-side descriptor data only** (the v0.13 `deny_unknown_fields` lesson: no new config-schema keys). **Every hook entry carries a purpose id** (`freshness` vs `learn`) (codex finding 5): the existing passive bootstrap (`bootstrap_hook_registrations`, run on every refresh/run) registers `learn`-purpose hooks only when `enabled` + per-machine activation hold — so an ordinary refresh can never re-add hooks after `load learn off` — and removal targets only `learn`-owned entries, never Cursor's existing freshness hook. Dialects: cursor flat JSON (machinery exists today); claude nested matcher schema (new writer). **Gemini gate: FAILED at plan time** (codex finding 4 anticipated this): a live plugin on this machine registered SessionEnd/AfterAgent/etc. entries in `~/.gemini/settings.json`, but the installed gemini-cli 0.45.2 bundle contains zero occurrences of any hook-event string — the entries are inert config the CLI never reads. Gemini therefore ships **tier-2** (no hook registration; its users stay covered by entry-point triggers + the gemini reader). Re-evaluate if a future gemini release documents hooks. Edits to agent settings files are **semantically preserving with timestamped backups, not byte-identical** (codex finding 7 — the existing writer re-serializes JSON; the promise is: no foreign keys touched, loadout-created empty containers removed on deregistration, backup written before first edit). Respect `disableAllHooks: true` in claude settings (register nothing, say so). Copilot (own-file, payload unverified) tier-2; codex hooks (experimental, trust-gated) and opencode (JS plugin) deferred.

## Audit layer — deferred to v0.16 (critic-driven cut)

`loadout-audit` (one-shot adversarial LLM review of rendered context) is severable and moves out, for three reasons found in review: (1) its findings had no defined lifecycle — no clearing action, and fingerprint churn (probe output changes the context hash on routine environment drift) would resurrect dismissed findings after every toolchain bump; (2) counting its call doubled the advertised spend ceiling; (3) it pushed the release to roughly twice v0.13's task count. What carries forward as settled design for v0.16: audit is the slow LLM layer on top of the v0.13 deterministic layer (redaction/lint/doctor stay synchronous, free, every write — that relationship is unchanged); audit keys on a fingerprint of **guidance content excluding volatile probe sections**; re-audit only on change; findings need their own disposition model (dismissed findings fed back as "previously rejected", auto-clear when the named fragment changes); it shares this release's worker, throttle, lock, log, and one-shot CLI helper. The `[learn]` config table and inbox schema (`kind` field) are designed so audit slots in additively.

## Error handling

- Every failure degrades to a log entry and, where user-visible, a warning naming the clearing action. No learning code path may block or fail a render, launch, or hook response.
- 2 consecutive failed runs (including stale-lock reclaims) → ambient triggering pauses; doctor/refresh surface "learning paused after repeated failures — see `load learn status`"; a successful manual `load harvest` or `load learn on` resets.
- Corrupt watermark file → treated like the trust store: loud warning, no silent reset; `load learn reset` re-baselines (harvests forward only).
- Malformed extraction output → failed run; the already-written spend stamp means no retry until the next tick.

## Testing

- Unit: watermark offset/rewrite semantics per store + pruning + monotonicity (regression attempts rejected); lock-token fencing (worker with a reclaimed-away token aborts every write phase); two-stamp semantics (empty scan leaves spend stamp untouched; crash after spend stamp burns the tick, nothing else); journal fold (multi-machine fixtures incl. machine-id rename), dedupe, suppression, disposition permanence; lock reclaim counted as failure; fast-path guards (enabled flag, ack, env vars, both stamps); reader fixtures for claude/codex/gemini incl. malformed lines and programmatic-session exclusion; redaction applied to slices and evidence; claim gate (injection-lint corpus → quarantine, never anchored); extraction-output validation (malformed JSON → failed run, watermark unmoved); pending-claim anchoring (same claim text → same id, count increments); hook purpose ids (refresh bootstrap never re-adds learn hooks when disabled; learn removal leaves freshness hooks intact).
- Integration: a stub agent CLI (script honoring the hygiene flags, emitting canned JSON) run end-to-end: trigger → detached worker → journal events + evidence store + log + advanced watermark; no-new-content run makes zero CLI calls; crash-after-stamp run costs the tick but nothing else; recursion guard (stub fires a nested `load hook` → no second worker).
- Hook writers: settings.json merge/remove round-trips preserve all foreign keys and values (semantic preservation; backups asserted; loadout-created empty containers removed on deregistration).
- Studio: inbox page render, promote writes config + disposition, dismiss suppresses.
- Suites stay green; clippy + rustfmt clean.

## Out of scope for v0.15.0

- The audit layer (v0.16 — see above). OS-scheduled triggering (rejected; `--ambient` entry preserved).
- cursor/opencode transcript readers; codex/opencode hook registration; Windows detach polish.
- Journal compaction (rule pre-committed: dispositions preserved forever); similarity-based suppression; prompt-side suppression hints; auto-promotion; assistant-message mining; cross-person aggregation (teams track).
- RS-3 journal capture (separate brainstorm).

## Assumptions and risks

- **Assumption:** the verified hook surfaces (claude SessionEnd, cursor stop) behave as documented for registration-by-file-edit; gemini's hook schema is plausible-but-unofficial (live plugin evidence, no doc) and is a gated verification task, not an assumption. Risk: vendor drift silently breaks hooks. Mitigation: doctor well-formedness check + no-trigger-in-14-days nudge + entry-point fallback keeps harvest alive regardless.
- **Assumption:** claude/gemini transcripts or payloads carry a usable interactive-vs-programmatic marker. Risk: they don't. Mitigation: stated fallback heuristic (Decision #6); this is a named plan-time verification task, not an implementation detail.
- **Risk:** transcript store formats churn (undocumented internals of fast-moving CLIs) — the highest ongoing maintenance surface. Mitigation: per-store fail-closed readers; formats re-verified per release.
- **Risk:** a user sees an unexplained `load`/`claude` process post-session (trust incident). Mitigation: consent text says exactly this will happen; argv reads `load harvest --ambient`; log + status + refresh line make every run attributable.
- **Risk:** metered-API spend. Mitigation: consent names CLI/model and a concrete per-run cost estimate; `learn.cli` pin; per-run usage logged; hard caps; stamp-first ordering; failure pause.
- **Risk:** prompt injection via transcripts (pasted web content in user messages). Mitigation: user-messages-only input, redaction, deterministic lint on candidate text at write, and the human promote gate before anything reaches rendered context.
- **Risk:** paraphrased resurfacing of dismissed claims (Decision #9 trade). Accepted for v0.15; documented; similarity matching is the v0.16+ answer.

## Validation

`cargo build`, `cargo test`, `cargo clippy --all-targets`, rustfmt. Manual dogfood on this machine: `load learn on` against real config; verify consent text (ceiling + cost line present); hook entries in `~/.claude/settings.json` + `~/.cursor/hooks.json` (+ `~/.gemini/settings.json` if its gate passed), each tagged with the learn purpose id; end a real claude session → worker fires once, log entry written, candidates staged, snapshot line appears; second session inside 6h → no second run; kill the worker mid-run → next tick runs, reclaim logged as failure, no extra spend within the tick; `LOADOUT_LEARN=off` suppresses; `load learn off` removes all learn-purpose hook entries (foreign keys and freshness hooks intact, backups present) and (after sync) dormants the second machine.

## Rollback

`load learn off` disables everywhere (synced flag) and deregisters locally. Deleting `state_dir/learn/` resets machine-local learning state (safe; next run re-baselines with the 14-day cutoff).
